# Rows in the chat

<p className="lead">In Claude Desktop and other clients that draw MCP Apps, the rows your agent gets show up right in the chat as a table you can sort, and a change it proposes shows up as a card that follows what you decide. One click opens either in Rowkery.</p>

## A query's rows

When the agent calls `query`, the chat shows Rowkery's view under the agent's message.

<Shot src="/img/rows-in-the-chat-rows.webp" width={720} height={278} alt="Rowkery's view in the chat: the shop connection with its prd tag, 6 rows in 12 ms, a table of orders with id, email, provider, total and created_at, the email column masked, and Open in Rowkery at the foot beside Same rows as the agent, 1 column masked." />

- **The same rows the agent got**, nothing more: the same checks, the same row limit, and the same stand-ins for [sensitive columns](/sensitive-columns-and-presenting/), shown dimmed.
- **The connection** and its environment tag, so you can tell prd from local at a glance.
- **Sort** by clicking a column header, or focus it and press <kbd>↵</kbd>. Click again to reverse. Numbers sort as numbers, and NULLs go last either way.
- **Wide results** scroll sideways inside the table. Hover a cell to read a long value in full. The button at the top right shows the view full screen, where the client offers it.
- **Open in Rowkery** brings Rowkery to the front with the agent's query in a new tab on that connection, and runs it at once. It opens in the window already on that connection, or in a new one. [Safe mode](/environments-and-safe-mode/) applies as it does to anything you run, and the query stays out of Recent queries.

A refused query shows Rowkery's reason instead of a table, the same text the agent gets.

## A proposed change

When the agent calls `propose_change`, the chat shows a card with each statement's verb and table, the agent's reason, how many rows it expects to change, and the SQL.

<Shot src="/img/rows-in-the-chat-proposal.webp" width={720} height={232} alt="A proposed change in the chat: UPDATE orders, expects 29 rows, the agent's reason, the UPDATE statement, Waiting for you at the top right, and Review in Rowkery at the foot beside Only you can commit it, in Rowkery." />

**Review in Rowkery** opens the Agents page on that change, ready for a [dry run](/proposed-changes/#the-dry-run). The card can't commit anything: only you can, in Rowkery.

While the card is on screen, it checks back every few seconds and shows what you decided: Committed with the rows changed, Rejected with your note, Commit failed, or Expired after 24 hours. The button goes once the change is decided.

<Shot src="/img/rows-in-the-chat-committed.webp" width={720} height={230} alt="The same card once committed: Committed, 29 rows at the top right, and Committed by you at 06:06 AM at the foot." />

## Which clients show it

Rowkery's view shows in clients that support MCP Apps, such as Claude Desktop, VS Code and Goose. Other clients, like Claude Code in a terminal, get the same text as before, and the agent's answer doesn't change either way.

**Open in Rowkery** and **Review in Rowkery** work on a Mac, with the installed Rowkery app. If the buttons don't show, the client can't call tools from a view, or Rowkery is running somewhere other than a Mac.

## What a button can open

The buttons don't send links through the chat. They ask Rowkery's MCP server, on your Mac, to open Rowkery, so the client shows no "Open external link" prompt.

- **A query button names a call, never SQL.** It carries the call's id and a random key from the [activity log](/choosing-what-to-share/#the-activity-log). Rowkery reads the SQL from the log, and opens only a query that its checks let through. A web page can't make Rowkery run anything, because it can't guess a key.
- **A call that's gone** from the log (cleared, or old enough to be rotated out) shows "That query isn't in Rowkery's activity log any more". A connection you've since deleted shows "That connection isn't in Rowkery any more".
- **A change that's no longer waiting** shows "That change isn't waiting for you any more" instead of opening another one.
- **No network.** The view is one page bundled with Rowkery. It loads nothing from the internet, and the client's sandbox wouldn't let it.
- Clicks in the view aren't written to the activity log. The query they open runs like any query you run yourself.

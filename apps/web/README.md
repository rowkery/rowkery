# Rowkery website (Next.js)

**The story** (2026-10-21, from the approved Whit-style mock): one black sheet, a floating nav that names the chapter you're in, big Gabarito titles over IBM Plex, and four chapters that play out as you scroll, each a tall section with one pinned stage. Dark only (2026-10-14): there is no light theme and no Appearance toggle.

- **Look:** the tokens, the nav, the hero, the close and the foot are in `app/globals.css`; the scenes in `components/story/story.css`; the sections under the close in `components/sections/more.css`. White pills are Download; grey pills are everything else. Orange is the one accent: the logo in the hero and the close, SQL keywords, the stand-ins, switches that are on, the penguins' props. No gradients, glows or blur.
- **Story** (agent first, then security, then ⌘K; the site must not read as "you need AI"): *Meet Rowkery.* (the logo between the words, a line naming what Rowkery is doing, *Postgres and SQLite on your Mac, with or without AI*, Download and See how it works); *Let your AI agent read your database* (it asks, Rowkery checks, sensitive columns come back as stand-ins, a change waits for Commit); *Security first* (the tables you share, a row as the agent gets it, the connection as it sees it); *Built for the keyboard* (⌘K, ⌘↵ and ⇧⌘P, the app's own chords, on big keycaps with a window behind); the page turns white for *Free. / Open source. / No account.*; *Get Rowkery.* with the unquarantine command over the colony; then connecting your agent beside the common questions, the email signup and a compact foot. Every word is real markup (`components/story/*Scene.tsx`), so it shows without scripts and gets indexed.
- **The penguin** (`Pg.tsx`): the mark itself, an inline path in an SVG with overflow visible, never redrawn and never a `<symbol>` behind `<use>` (a symbol clips to the view box that uses it, which cut penguins off in the first mock). Props are drawn beside it in orange (a hat, shades, a magnifier, a letter, a sign, a key); poses are transforms only. In the hero and the close it is the logo, so it stays the plain mark there: no props, no hops, no flips; it only moves as a whole (its entrance, the flight, a small drift toward the pointer). The scenes, the colony and the parade are where penguins play. Every penguin stands whole: on the agent window's top edge, on the last keycap (a child of the key, so it tilts and presses with it), beside the security card (on top of it on a phone), on the signup card, and in the colony on the ground line with even gaps (fewer and smaller on a phone).
- **Motion** (`components/story/engine.ts`): the story plays only with scripts and without Reduce Motion; a line in `app/layout.tsx` marks the page `data-motion` before the first paint so the pinned layout is there from the start. The hero holds its screen (sticky, a screen and a flight long) while the words part and the logo flies into the brand in the nav: the logo is fixed to the screen and the flight is measured once in `layout()`, so no frame corrects for the scroll (a phone scrolls off the main thread, and a scroll term made the old flight jitter there); the words are clipped at their inner edges, so they never pass behind the logo's belly. Scroll drives a damped position through the hero and each scene; one requestAnimationFrame loop runs while anything is settling and stops after, and scroll, resize and the pointer wake it. It moves transform and opacity on HTML boxes only, writes a style only when its value changes, and runs nothing on a timer: the line under the hero's logo cycles on CSS keyframes, the key presses are CSS animations with delays switched on by a class. Exits are quicker than entries, and each scene ends as its pieces finish leaving: the sections overlap, so the next stage (see-through, its title rising) is already scrolling in, and no empty screen is scrolled between scenes. Under Reduce Motion or without scripts each scene is a plain stack with every step's result showing. The pinned scenes need the engine to show anything, so the page falls back to that stack whenever it isn't running: the head script drops `data-motion` if the page's own scripts fail to load, or if the engine (`data-story`) hasn't started 4 s after load, and the engine drops it, taking back every style and text it wrote, if it throws. Typing "rookery" sends a parade across.
- **Copy facts:** one-click setup is only for Claude Desktop and Claude Code; any other MCP client runs `Rowkery --mcp`. No offline claims (the app checks for updates). No millisecond figures on the page until the known window-switch slowdown is fixed. No signing promises: the Mac app isn't signed yet, and sponsors cover the developer fee. The agent's limits on the page (1,000 rows at most, 10 s) are `MAX_ROWS` and `STATEMENT_TIMEOUT` in `crates/rowkery-mcp/src/guard.rs`; agents get a masked host and never the user or password. Headings carry no full stops except *Meet / Get Rowkery.* and *Free. / Open source. / No account.*
- **Fonts** (all SIL OFL, self-hosted from `app/fonts` through `next/font/local`): Gabarito (variable, 400 to 800) for headings, IBM Plex Sans (400, 500) for body text, IBM Plex Mono (400, 500) for code and labels.
- **Stack:** Next.js (App Router, TypeScript), static export, plain CSS.

```bash
npm install
npm run dev        # http://localhost:3000 with hot reload
npm run build      # static site in out/
```

Or `make web` from the repo root (build + serve `out/` on :3000).

**Deploy:** Vercel (or Cloudflare Pages), root directory `apps/web`, build command `npm run build`, output directory `out`.

**Placeholders:** `DOWNLOAD_URL` and `RELEASE` in `lib/site.ts`. Every Download button links to `DOWNLOAD_URL`, and while it is empty they scroll to the close. `RELEASE` is the build named in the close's line about the unsigned alpha.

**Check** (after `npm run build`; Playwright in Chromium only, so Safari and a real Mac are Lucas's to check). `scripts/story.mjs` names the story's moments the checks scroll to.

- `node scripts/penguin-proof.mjs [w h]` proves every penguin is whole at nine window sizes (1440x900, 1280x800, 1024x768, 1920x1080, 820x1180, 390x844, 430x932, 375x667, 360x740): at each moment it samples points inside each visible penguin's fill and hit-tests them with every layer made hittable; anything else on top that paints there (a see-through box doesn't count; the hero's logo landing on the brand is the same mark laid over it), or a penguin at rest cut by the screen's edge, fails. Then it sweeps the hero's flight and every pinned scene a tenth of a unit at a time (a reader can stop anywhere): no penguin that shows at all may be covered, and one may be cut by the screen's edge only while it enters or leaves. Then the colony scrolled in, halfway and out: every bird on the ground line, none touching another. Prints "all penguins whole". The nine sizes run side by side, and at each step the story jumps straight to where it would come to rest (a test-only hook, `window.__story.snap()`, there only when the check asks before the page loads), so the run takes about a minute.
- `node scripts/story-proof.mjs [dir]` photographs each moment at 1440x900 and 390x844 and checks the nav's chapter, the lit caption, the titles, the white page's words, the close in full view under the nav and the phone's dock stepping aside for it. One contact sheet per size.
- `node scripts/resolution-check.mjs [dir]` photographs the story at eight window sizes (360 to 2560 wide) and reports sideways scroll, the hero off screen, text cut off or broken onto two lines, scene pieces running off the side and the job cycle not running. Then Reduce Motion (nothing moves or pins, one job, every step's result showing), no scripts (the same stack, in reading order), the story failing to run (its scripts blocked, or the engine throwing: the same stack, with nothing it wrote left behind), and the 404. Fails on any page error.
- `node scripts/redesign-proof.mjs [dir]` proves the 2026-10-21 redesign at 1440x900 and 390x844: the fonts, every word in the served HTML (and no millisecond figure or offline claim), the section order, picking the hero's line, See how it works, each chord's keys, the discs, the unquarantine Copy, the dock, the connect card's tabs and Copy, the questions and the parade. Writes frames of each.
- `node scripts/flight-proof.mjs [dir]` proves the hero's flight at 390x844, 375x667 and 1440x900: the held screen's top stays at 0 through the flight, the logo is the plain mark, and just before it hides its body lands on the brand's mark within 1 px in place and size. Writes frames at progress 0, 0.25, 0.5, 0.75, 0.95 and 1.
- `node scripts/follow-proof.mjs [dir]` proves the email signup under the close with Kit stubbed: its place, the penguin standing on the card clear of text, the address posted as `email_address`, the confirm message, the error that keeps the address (and leaves the field still), and the plain-form fallback when Kit is unreachable. Needs `KIT_FORM_ID`.
- `node scripts/scroll-profile.mjs` scrolls the page top to foot in Chromium with the CPU slowed 4x and reports frame gaps and the main thread's style, layout and paint work, scrolling and sitting still (at the top, in a scene, on the close). It fails if the page lays out or paints while it sits still, or if the engine's frame loop keeps asking for frames once settled. Two traps it caught before: an animation on a shape inside an SVG repaints every frame, and so does an animation inside a box that is itself moving.
